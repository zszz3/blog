# 内推投稿服务

内推页面本身仍由 GitHub Actions 发布。在线投稿和删除需要阿里云 ECS 上额外运行 `server/neitui_api.py`，并让现有 Caddy 把 `/api/neitui` 转发给它。普通博客发布账号只能传静态文件，不能安装或启动这个服务；首次启用需要服务器管理员操作。

服务使用 SQLite 数据库和独立 Docker volume。访客先填写三项信息，最后输入投稿密码；删除使用另一组密码。两组密码只放在服务器的 `deploy/neitui.env`，不得提交到 GitHub。服务不开放容器端口，仅通过现有 Caddy 接收 HTTPS 请求。新增和删除都会立即反映在页面上；删除会从数据库移除联系方式，仅保留条目标识与删除时间，避免启动时重新导入初始条目。

在服务器上取得本仓库源码后，将两组不同密码写入源码目录下的 `deploy/neitui.env`：

```dotenv
NEITUI_ADD_PASSWORD=<投稿密码>
NEITUI_DELETE_PASSWORD=<删除密码>
NEITUI_DB_PATH=/data/neitui.sqlite3
```

将文件权限设为 `600`。使用 `deploy/compose.neitui.yaml` 启动 API，然后把仓库的 `deploy/Caddyfile` 更新到现有 `/opt/wojiecihuo/deploy/Caddyfile`，验证并重载 `wojiecihuo-blog` 容器中的 Caddy。启用前先备份旧 Caddyfile；数据库 volume 应纳入服务器备份。

验证：访问 `https://wojiecihuo.cn/api/neitui` 应返回包含 `referrals` 的 JSON；页面应显示投稿表单。用真实密码试投一条可公开的测试信息，确认出现后用删除密码撤下，再检查页面已隐藏它。首次运行会将 `src/data/neitui.json` 中已有的公开内推信息写入数据库；重复启动不会重复导入或恢复已删除的条目。

API 上线并验证后，将 GitHub Actions 仓库变量 `NEITUI_API_ENABLED` 设为 `true`，重新发布静态页面。启用后，页面不再把初始条目写进 HTML；API 暂时不可用时会显示错误状态，不会重新公开已删除的联系人。

本地开发可先以临时密码运行 `server/neitui_api.py`，再运行 `pnpm dev`。Astro 开发服务器会把 `/api/neitui` 转发到 `127.0.0.1:8080`；如需其他地址，可设置 `NEITUI_API_DEV_URL`。
