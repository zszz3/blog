## 每次写作

将 Markdown 与引用的图片一起放进 `src/content/posts/文章目录/`。填写标题、发布日期、简介、标签和分类；`draft: true` 为草稿，发布前改为 `false`。上传主分支后，GitHub Actions 自动检查、构建并发布完整网站，包含搜索索引和 RSS。到仓库的 Actions 页面查看本次提交，`build` 和 `deploy` 都成功后，刷新正式网站即可。

## 当前服务器配置

现有 `multi-agent-cloud-nginx-1` 继续监听 80 端口并服务原 API。博客使用独立容器 `wojiecihuo-blog`，监听 TCP 443；安全组已放行该端口。两者通过现有 Docker 网络 `multi-agent-cloud_default` 连通。

使用 `deploy/compose.existing-proxy.yaml` 和 `deploy/Caddyfile` 启动博客。`deploy/nginx-existing-proxy.conf` 的域名入口已追加到 `/opt/multi-agent-cloud/nginx/default.conf`，校验通过后平滑重载 Nginx。原配置备份在 `/opt/wojiecihuo/deploy/nginx-default-before-blog-20260921.conf`。

不要在这台服务器直接启动独占 80 端口的 `deploy/compose.yaml`。该文件仅供没有现成反向代理的环境使用。

目录示例：

```text
/opt/wojiecihuo/
├── deploy/
│   ├── Caddyfile
│   └── compose.existing-proxy.yaml
└── site/
    ├── releases/
    ├── shared/
    └── current -> releases/已发布版本
```

站点文件归系统账号 `wojiecihuo` 所有，其 SSH 连接只能使用专用发布入口，不能交互登录。日常构建在 GitHub Actions 中完成，服务器上的 root 所有的 `/usr/local/lib/wojiecihuo-publisher/release.py` 负责验证和切换版本。Caddy 以只读方式挂载 `site/`，证书保存在独立的 Docker volume 中。服务器原有 `/opt/wojiecihuo/tooling/` 与 `sources/` 保留，供必要时手动构建使用。

## 自动部署配置

发布使用专用 SSH 密钥，以 `wojiecihuo` 身份接收 GitHub 构建好的静态文件，不在服务器重新构建。部署连接只接受 `publish`、`rollback` 和 `status`，不提供交互式终端、任意命令、SFTP 或端口转发。发布范围固定为 `/opt/wojiecihuo/site`。

首次接入时，将专用 Ed25519 公钥传到服务器，由管理员执行：

```sh
bash deploy/install-ssh-publisher.sh /path/to/github-actions.pub
```

安装脚本会备份原有 SSH 配置，把验证及发布程序放入 root 所有的 `/usr/local/lib/wojiecihuo-publisher/`，校验限制生效后重载 SSH。私钥只保存在该仓库的 GitHub Actions secret 中。先核对服务器主机公钥，并测试专用密钥只能运行发布命令，再打开自动部署开关。

在 GitHub 仓库设置以下 Actions 变量：

| 名称 | 内容 |
| --- | --- |
| `ECS_HOST` | ECS 公网地址 |
| `ECS_USER` | `wojiecihuo` |
| `ECS_PORT` | SSH 端口，默认 22 |
| `ECS_SITE_ROOT` | `/opt/wojiecihuo/site`，与服务端限制一致 |
| `PUBLIC_ICP_NUMBER` | `皖ICP备2026032301号`，未设置时使用网站配置中的同一备案号 |
| `ECS_DEPLOY_ENABLED` | 确认服务器配置完成后设为 `true` |

设置 Actions secrets：

- `ECS_SSH_KEY`：部署账号的专用 SSH 私钥。
- `ECS_KNOWN_HOSTS`：通过可信渠道核对过的服务器主机公钥记录。

不开启部署时，Actions 会保留网站构建文件并说明部署尚未启用。不要把密钥写进仓库。

## 发布与回退

每次提交生成一份完整版本。服务器先验证页面、RSS 与搜索索引，再切换 `current`；构建或验证失败不覆盖当前版本。旧页面用到的带内容指纹的资源会保留，以减少切换时的图片或搜索加载失败。

需要回退时，在 GitHub Actions 手动运行 `Build and publish blog` 工作流，选择 `rollback`，版本填写 `previous`。也可指定已发布的版本编号。回退不会改动文章原稿；回退后请同步修正主分支，否则下一次提交仍会发布主分支的内容。

每次发布后检查正式域名的 HTTPS、主要页面、搜索索引、图片、RSS 和备案链接；以实际访问结果确认发布成功。
